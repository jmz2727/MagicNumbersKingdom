# مملكة الأعداد السحرية — تطبيق أندرويد مستقل 1.5.0

هذه نسخة Android من المنهج المختبر نفسه: ٢٠ مستوى، الأعداد ١–١٠٠، السحب والإفلات فقط في الاختبارات، حديقة الأغنام، أسئلة العشرات والآحاد، تصحيح الأخطاء ومراجعتها، النجوم والشهادات. كل الأصوات المائة مضمنة داخل APK. لا يحتاج التشغيل إلى ChatGPT أو حساب أو إنترنت، حتى في أول مرة.

## حالة التسليم

هذا **مشروع بناء أندرويد**، وليس ملف APK. يجب أن ينجح مسار GitHub Actions وتُفحص نتيجة التوقيع قبل تسمية الناتج جاهزًا للتثبيت. لم تُجرَ عملية Android Gradle أو تجربة هاتف في بيئة التأليف لعدم وجود Android SDK فيها. اجتازت المصادر ٥٧ اختبار Node و٣٨ تحقق Java مستقلًا. لا توجد مكتبات تشغيل خارجية أو AndroidX أو خادم خارجي.

## إنتاج APK وحفظ مفتاح التوقيع محليًا

المستودع العام معتمد من المالك. يُنشر الكود والموارد فقط؛ لا يحتوي المستودع على مفتاح توقيع أو كلمات مرور أو بيانات طفل. يبقى الموقع المستضاف السابق منفصلًا بإعدادات وصوله الحالية.

1. عند الدفع إلى `main`، أو تشغيل **Build offline Android app** من Actions، تُنفّذ الاختبارات ثم بناء Release دون توقيع. لا يحتاج GitHub إلى أسرار توقيع.
2. ناتج Actions باسم `Magic-Numbers-Android-Build` يحتوي APK غير موقّع ومُحاذى، وأداة `apksigner.jar` من Android SDK الموجود في بيئة البناء، وتقرير البناء وبصمات SHA256. الملف غير الموقّع لا يُثبَّت مباشرة.
3. على جهاز البناء الموثوق به Java/keytool، أنشئ مفتاحًا مرة واحدة: `python3 scripts/create_signing_key.py`. احتفظ بمجلد `.signing/` خارج Git وبالنسخة الاحتياطية الخاصة؛ لا تشاركه مع التطبيق.
4. نزّل ناتج Actions وفكّه في مجلد، ثم وقّع محليًا: `python3 scripts/sign_apk.py BUILD_DIRECTORY Magic-Numbers-Kingdom-1.5.0.apk`. يفحص السكربت البصمات ومحتويات APK قبل التوقيع وبعده، ويتحقق من صحة التوقيع.
5. شارك ملف APK الموقّع فقط وثبّته على الهاتف. يبدأ الهاتف الجديد من المستوى الأول ويعمل دون إنترنت من أول تشغيل.

كل تحديث لاحق يستخدم المفتاح و`applicationId` نفسيهما، مع زيادة `versionCode`. احتفظ بالمفتاح للتحديث دون حذف بيانات الطفل. لا تُرسل المفتاح أو كلمات مروره إلى GitHub أو سجلات البناء.

## الفحص قبل البناء

باستخدام Node الموجود دون npm install:

```sh
python3 scripts/prepare_assets.py
npm test
mkdir -p build/policy-test
javac -d build/policy-test app/src/main/java/com/jameel/magicnumbers/AssetPolicy.java tests/AssetPolicyTest.java
java -cp build/policy-test com.jameel.magicnumbers.AssetPolicyTest
```

يستخدم البناء Gradle 8.11.1 وAGP 8.9.2 وJDK 17 وAndroid SDK 35؛ الحد الأدنى Android 8.0 (API 26). يتولى setup-gradle توفير Gradle، فلا يعتمد البناء على وجود gradlew. الموارد الصوتية الأصلية نحو ١٫٥٥ ميغابايت؛ حجم APK النهائي لا يُعلن قبل إنتاجه فعليًا.

## الحفظ والنقل

- يُحفظ التقدم داخل التخزين المحلي الخاص بالتطبيق، منفصلًا عن Chrome ونسخة الموقع.
- «تقدمي ← تصدير التقدم» يفتح منتقي ملفات أندرويد لحفظ JSON بالمكان المختار، دون صلاحية تخزين عامة.
- «تقدمي ← استعادة نسخة» يقرأ ملفًا مختارًا، بحد ٦٤ كيلوبايت، ويفحص مخططه قبل طلب تأكيد استبدال التقدم.
- يمكن مشاركة APK مع هاتف آخر ليبدأ من جديد، أو نقل JSON إذا أردت الاحتفاظ بالتقدم.
- الشهادات تستخدم نافذة الطباعة/حفظ PDF في أندرويد.

## فحص قبول الهاتف بعد إنتاج APK

- ثبّت APK على هاتف دون ChatGPT، وفعّل وضع الطيران **قبل أول تشغيل**؛ يجب فتح المستوى الأول وتشغيل صوت العدد ١ فورًا.
- أكمل المستوى الأول بإجابات مسحوبة، وخطأ متعمد، ثم التصحيح والمراجعة. تأكد من فتح المستوى الثاني بعد الإكمال فقط.
- أغلق التطبيق بالقوة وأعد فتحه؛ افحص النجوم والجلسة المستمرة. جرّب التدوير والخروج أثناء تشغيل الصوت.
- صدّر JSON، واستعده على تثبيت مستقل. جرّب إلغاء الاستيراد وملفًا تالفًا؛ يجب بقاء التقدم.
- افحص المستويات ١٠ و٢٠، وصفر الآحاد، والعشر عشرات للمائة، وصوت ١٠٠، والمقارنة والسابق والتالي وخانة «؟».
- جرّب طباعة شهادة؛ راجع التخطيط واللمس والوضوح الصوتي فعليًا. المحاكاة البرمجية وحدها لا تثبت ذلك.
